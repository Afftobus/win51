# Win51 — виртуальная звуковая карта 5.1 с выводом Dolby Digital (AC-3) по HDMI

[English version](README.md)

Win51 добавляет в Windows устройство вывода 5.1. Всё, что на него играет (игры, браузер, системные звуки), в реальном времени кодируется в AC-3 и уходит по HDMI битстримом — так же, как при «пробросе AC-3» в плеере. Телевизор передаёт этот битстрим на оптический выход, ресивер за ним декодирует честные 5.1. Звуковые карты с Dolby Digital Live делают это аппаратно, а HDMI-звук видеокарт — нет.

```
 приложения ──► «Динамики (Win51 AC3 5.1)» ──► win51svc ─────────────────► HDMI ──► ТВ ──► оптика ──► ресивер
                виртуальный 6-канальный выход  AC-3 640 кбит/с, IEC 61937    битстрим         S/PDIF     декодирует 5.1
                (драйвер ядра)                 (служба)
```

**Зачем это нужно.** По оптике (S/PDIF) ресивер получает либо стереосигнал PCM, либо сжатый поток вроде AC-3 или DTS. Многие телевизоры к тому же сообщают компьютеру по HDMI (в EDID), что принимают только стерео PCM. Поэтому объёмный звук на ресивере есть, только когда плеер пробрасывает дорожку AC-3/DTS без изменений, а игры, которые выдают многоканальный PCM, звучат в стерео. Win51 на лету кодирует этот многоканальный PCM в AC-3.

## Состояние

Работает каждый день на одной системе: Windows 10 22H2, HDMI NVIDIA RTX 2060 → телевизор LG (2018) → оптика → AV-ресивер. На этой системе проверено:

- раскладка всех шести каналов, включая сабвуфер (встроенный тестовый сигнал);
- обычный звук Windows идёт в 5.1;
- поток восстанавливается после выключения и включения телевизора и после пересогласования HDMI;
- служба сама перезапускается после сбоя.

Другие видеокарты, Windows 11 и другие телевизоры пока не проверялись — отчёты приветствуются.

## Заработает ли у меня?

Скорее всего, да, если выполнено всё из этого списка:

| Требование | Почему |
|---|---|
| Windows 10 2004 (сборка 19041) или новее либо Windows 11, x64 | INF рассчитан на 10.0.19041+. На Windows 11 должно работать, но не проверялось. |
| Выход, принимающий проброс AC-3 в монопольном режиме WASAPI | Служба сама выбирает выходы HDMI/DisplayPort (видеокарты почти всегда их поддерживают). Выход S/PDIF тоже подойдёт, если указать его через `-Out`. Что принимает AC-3, показывает `win51svc list`. |
| Дальше по цепочке есть декодер AC-3 | Если проброс AC-3 из плеера уже даёт 5.1, то и это даст. На телевизоре цифровой аудиовыход должен стоять в *Авто / Bitstream / Pass-through*, а не в *PCM*. |
| **Secure Boot выключен, тестовый режим Windows включён** | Драйвер подписан самоподписанным тестовым сертификатом (см. ниже). |

### Про тестовую подпись

64-битная Windows загружает драйверы ядра, только если их подписала Microsoft. Для драйвера «для всех» нужна *аттестационная подпись* Microsoft: EV-сертификат подписи кода и аккаунт в Windows Hardware Dev Center. Этого пока нет. До тех пор драйвер подписан тестовым сертификатом, а это значит:

- В UEFI нужно выключить Secure Boot, тестовый режим включается командой `bcdedit /set testsigning on`. Если включён BitLocker, сначала приостановите его, иначе после изменения Windows спросит ключ восстановления.
- В углу рабочего стола появляется надпись «Тестовый режим».
- Игры с античитом уровня ядра (Riot Vanguard, FACEIT, часть игр с Easy Anti-Cheat/BattlEye) в тестовом режиме не запускаются. Офлайн-игры и защиты вроде Denuvo это не затрагивает.
- Каждая машина, на которой собирают проект, создаёт свой тестовый сертификат, а компьютеры, на которые ставят драйвер, ему доверяют. Доверие сертификату означает доверие всему, что им подписано, поэтому лучше собрать проект самому, чем ставить чужие тестовые сборки.

## Как это устроено

### Драйвер (`driver/`)

Минипорт PortCls WaveRT (KMDF 1.15) на основе примера Microsoft [SimpleAudioSample](https://github.com/microsoft/Windows-driver-samples/tree/main/audio/simpleaudiosample). Это корневое устройство (`ROOT\Win51`) с одним выходом и без реального железа.

- **Форматы.** 48 кГц, 6 каналов: 32-битный float, PCM 24 бита в 32 или PCM 16 бит. Каждый формат идёт с маской каналов `0x60F` (5.1 с боковыми тылами) и `0x3F` (5.1 с задними тылами). Формат и конфигурация колонок по умолчанию — float, 5.1 с боковыми тылами.
- **Часы.** Позиция буфера вычисляется по времени QPC, а таймер высокого разрешения раз в 1 мс сигналит о заполнении буфера (событийный режим). Сами данные драйвер не трогает: Windows смешивает звук в буфер WaveRT, служба забирает этот микс через loopback.
- **Громкость.** Узлов громкости и mute нет, поэтому ползунок громкости Windows применяет программно, и он попадает в закодированный поток.
- **Один поток.** У выхода один системный входной пин, его занимает аудиодвижок Windows.
- **Отличия от примера.** Убраны массив микрофонов, генератор тона и запись в WAV. Добавлены форматы 5.1. Исправлено 32-битное переполнение в расчёте позиции: 6 каналов float — это 1,15 МБ/с, и без обновления позиции около 3,7 с счётчик переполнялся.

### Служба (`service/`)

`win51svc.exe` работает как служба Windows *Win51 AC3 encoder*. Конвейер:

1. **Захват.** WASAPI loopback забирает микс выхода Win51: 48 кГц float, любая маска 5.1, каналы раскладываются в порядок FL FR FC LFE SL SR; задние тылы сводятся в боковые.
2. **Буфер.** Очередь держится на 45 мс (`--target-ms`) в момент, когда забирается очередной кадр AC-3. Loopback и HDMI работают от разных часов:
   - расхождение исправляется выбрасыванием или повтором одного сэмпла, когда сглаженный уровень выходит за ±1 мс;
   - в начале воспроизведения перед звуком подкладывается тишина, поэтому старт ровно попадает в целевой уровень и ничего не обрезается;
   - если вывод застрял, буфер догоняет сразу, а не подрезается понемногу.
3. **Кодирование AC-3.** Энкодер `ac3` из libavcodec: 640 кбит/с (`--bitrate`), 1536 сэмплов в кадре, около 0,1 мс на кадр на i7-8700K.
4. **Упаковка IEC 61937.** Каждый кадр заворачивается в пакет 6144 байта: преамбула `Pa=0xF872 Pb=0x4E1F Pc=AC-3|bsmod Pd=длина`, полезная нагрузка с перестановкой байтов в 16-битных словах, добивка нулями. Это тот же сигнал, что отдаёт плеер при пробросе AC-3.
5. **Вывод на HDMI.** WASAPI в монопольном событийном режиме, период 10 мс (`--period-ms`), формат `KSDATAFORMAT_SUBTYPE_IEC61937_DOLBY_DIGITAL`, 2 канала / 16 бит / 48 кГц; если он не принимается, используется `WAVE_FORMAT_DOLBY_AC3_SPDIF`. Поток работает с приоритетом MMCSS «Pro Audio».

Вывод не останавливается. Когда ничего не играет, служба продолжает слать закодированную тишину: ресивер остаётся в Dolby Digital, и начало звука не теряется на повторную синхронизацию.

Когда телевизор выключают или HDMI пересогласуется, служба ждёт и снова открывает выход — обычно через 1–2 с после его появления. На S/PDIF сама она не переключается.

На эталонной системе часы драйвера (QPC) и часы HDMI не расходились заметно: за 17 с лишним минут воспроизведения коррекций не понадобилось. Служба занимает около 0,6 % одного ядра.

### Задержка

Это оценка по параметрам; сквозная задержка не измерялась.

| Этап | Время |
|---|---|
| Период аудиодвижка Windows (плюс буфер самого приложения) | 10 мс |
| Пакет loopback | до 10 мс |
| Буфер, включая набор кадра AC-3 из 1536 сэмплов | 45 мс |
| Буфер HDMI | 10 мс |
| Передача кадра AC-3 внутри пакета IEC 61937 (640 кбит/с) | ~13 мс |
| Перекрытие окон декодера AC-3 (256 сэмплов) | 5,3 мс |
| **На стороне ПК, до декодера ресивера** | **≈ 85–95 мс** |

К этому добавляются проброс в телевизоре и обработка в ресивере. Сам формат AC-3 стоит около 50 мс: кадр 32 мс, его передача и перекрытие окон декодера. Остальное — буферы, которые можно уменьшить (см. «Идеи»).

Windows об этой задержке не знает, поэтому видеоплееры её не компенсируют. Если губы опережают звук, сдвиньте звук в плеере примерно на −90 мс.

## Сборка

Нужен компьютер с Windows 10/11 x64 (можно тот же, на который ставите) и права администратора:

- **Enterprise WDK (EWDK)**: ISO со [страницы загрузки WDK](https://learn.microsoft.com/windows-hardware/drivers/download-the-wdk). Это самодостаточный набор из компилятора, WDK и SDK, ставить ничего не нужно. Проверено с EWDK 28000 (Visual Studio 2026 Build Tools).
- **FFmpeg**: 64-битная сборка *lgpl-shared*, например `ffmpeg-n8.1-latest-win64-lgpl-shared-8.1.zip` с [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds/releases), распакованная. Нужен FFmpeg 5.1 или новее (API раскладок каналов); проверено на 8.1.

Положите оба в `deps\` в репозитории (git его игнорирует) или передайте через `-Ewdk` / `-Ffmpeg`:

```
deps\EWDK_28000.iso
deps\ffmpeg-n8.1-latest-win64-lgpl-shared-8.1\{bin,include,lib}
```

Сборка, в PowerShell от администратора:

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1            # -DriverOnly / -ServiceOnly / -Configuration Debug
```

Скрипт подключает ISO и собирает оба проекта с `/W4 /WX`. При первом запуске он создаёт тестовый сертификат `CN=Win51 Test Signing` в `Cert:\LocalMachine\My`, затем подписывает `win51.sys`, создаёт и подписывает каталог и собирает установочную папку `out\win51\`:

```
out\win51\
  driver\    win51.sys  win51.inf  win51.cat  win51-test.cer  devcon.exe
  service\   win51svc.exe  avcodec-*.dll  avutil-*.dll  swresample-*.dll  FFMPEG-LICENSE.txt
  enable-testsigning.ps1  install-driver.ps1  install-service.ps1
  uninstall-service.ps1   uninstall-driver.ps1  disable-testsigning.ps1
  LICENSE.txt  LICENSE-MS-PL.txt
```

## Установка

Скопируйте `out\win51\` на целевой ПК. Если папка пришла скачиванием, выполните в ней `Get-ChildItem -Recurse | Unblock-File`. Дальше — в PowerShell от администратора в этой папке:

1. Выключите Secure Boot в UEFI. Если включён BitLocker, сначала приостановите его: `Suspend-BitLocker -MountPoint C: -RebootCount 1`.
2. Включите тестовый режим и доверие сертификату, затем перезагрузитесь:
   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\enable-testsigning.ps1
   ```
3. Установите драйвер и службу:
   ```powershell
   .\install-driver.ps1
   .\install-service.ps1                 # или .\install-service.ps1 -Out "S/PDIF", чтобы выбрать выход
   ```
4. Настройте Windows. В *Панели управления → Звук*:
   - сделайте **«Динамики (Win51 AC3 5.1)»** устройством по умолчанию;
   - в его *Свойствах → Дополнительно* снимите **«Разрешить приложениям использовать устройство в монопольном режиме»**. Программа, открывшая Win51 монопольно, идёт мимо микшера Windows, и вместо её звука будет тишина.
5. В плеерах выводите звук на Win51 (или на устройство по умолчанию) с декодированием в PCM. HDMI-выход занят службой, напрямую плеер на него битстрим не отправит.

Обновление: соберите заново и ещё раз запустите `install-driver.ps1` и `install-service.ps1`, оба обновляют установку на месте.

Удаление: `uninstall-service.ps1`, `uninstall-driver.ps1`, `disable-testsigning.ps1`, перезагрузка, затем верните Secure Boot.

## Командная строка `win51svc`

Установленная копия лежит в `C:\Program Files\Win51`. Командам `tone` и `run` нужен HDMI-выход, поэтому сначала остановите службу (`Stop-Service win51svc`), а после запустите снова.

```
win51svc list                    выходы: какие принимают AC-3 ([AC3 passthrough]) и какой будет выбран ([auto output])
win51svc tone                    тест каналов: шум по очереди на ФЛ, Ц, ФП, ТП, ТЛ, затем свип 35-90 Гц на сабвуфер; драйвер не нужен
win51svc run                     кодировать то, что играет на Win51 (то же, что делает служба), в консоли
win51svc service                 то же, под диспетчером служб

параметры tone / run / service:
  --out <имя>|none               выход (часть имени); по умолчанию HDMI/DisplayPort, принимающий AC-3;
                                 none — без вывода, закодировать --seconds секунд как можно быстрее
  --in <имя>                     какой выход захватывать (по умолчанию Win51)
  --bitrate <кбит/с>             битрейт AC-3, по умолчанию 640 (максимум для AC-3)
  --period-ms <мс>               период монопольного режима HDMI, по умолчанию 10
  --target-ms <мс>               целевой уровень буфера, по умолчанию 45
  --seconds <n>                  остановиться через n секунд
  --only fl|fr|fc|lfe|sl|sr      tone: только один канал
  --dump <файл>                  дополнительно писать поток IEC 61937 в файл (s16le stereo)
  --log <файл>                   дополнительно писать журнал в файл
```

## Диагностика

Служба пишет журнал в `C:\ProgramData\Win51\win51svc.log`. После 10 МБ он переименовывается в `win51svc.log.old` и начинается заново, так что на диске не больше ~20 МБ — это примерно 1–2 недели истории. Раз в 10 с служба добавляет строку вида:

```
AC3 frames 316 (failed 0), encode avg 0.12 / max 0.20 ms; capture 486720 frames (0 silent), buffer 1924..2308 frames,
underruns 0, drop/repeat 0/0, resyncs 0, overflow 0, discontinuities 0
```

| Поле | Норма | Что значит |
|---|---|---|
| `AC3 frames` | 312–318 | Кадров отправлено за 10 с (31,25 в секунду). Меньше — значит, HDMI-выход был недоступен. |
| `failed` | 0 | Ошибки кодирования или упаковки. |
| `capture` | ~480 000, пока играет звук; 0 в тишине | Сколько кадров пришло из микса Win51. Когда никто не играет, Windows ничего не присылает. |
| `buffer` | примерно 1900..2300 | Уровень буфера (в кадрах по 48 кГц) в момент, когда забирается кадр AC-3. |
| `underruns` | 0, или 1 при остановке звука | Буфер опустел. Посреди воспроизведения — значит, был разрыв в захвате. |
| `drop/repeat` | 0/0, изредка единицы | Коррекции расхождения часов, по одному сэмплу. |
| `resyncs` | 0 | Вывод застрял, буфер перескочил вперёд. |
| `overflow` | 0 | В очереди накопилось больше 1 с. |
| `discontinuities` | 0, или 1 при старте | Флаги сбоев от loopback Windows. |

Проверить кодировщик и порядок каналов без колонок: записать поток в файл и раскодировать его FFmpeg:

```powershell
win51svc tone --out none --seconds 12 --dump tone.spdif
python tools\analyze_dump.py tone.spdif    # нужны Python 3 и ffmpeg/ffprobe в PATH; печатает уровни по каналам
```

## Ограничения

- Только тестовый режим (см. «Про тестовую подпись»).
- Только AC-3, максимум 5.1. В AC-3 нет 7.1, кодировщиков DTS и E-AC-3 нет.
- HDMI-выход монопольно занят службой. Чтобы пробросить из плеера DTS, TrueHD или E-AC-3, службу нужно остановить. Дорожки AC-3 и DTS, проигранные через Win51, декодируются и заново кодируются в AC-3 640 кбит/с.
- Нет апмикса. Стерео звучит только из передних левой и правой колонок: Windows не апмиксит, а ресивер видит поток 5.1, и его собственный апмикс не включается.
- Только 48 кГц, остальные частоты Windows пересэмплирует.
- Задержка не сообщается Windows, автоматической синхронизации губ нет (см. «Задержка»).
- Только x64.

## Идеи

- Меньше задержка: период HDMI 3 мс, меньший буфер и получение звука напрямую от драйвера с тактированием от HDMI вместо loopback.
- Сообщать задержку конвейера через позицию потока, чтобы плееры сами держали синхронизацию.
- Аттестационная подпись, чтобы драйвер ставился без тестового режима.
- Вариант с DTS (в libavcodec есть экспериментальный кодировщик DTS).
