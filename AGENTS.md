# AGENTS.md

Guidance for AI coding agents working on this repository. The human-facing documentation is [README.md](README.md) (English) and [README.ru.md](README.ru.md) (Russian). Read README.md first: it explains the design, the latency budget and the log format.

## What this is

Win51 is a virtual 5.1 audio output for Windows whose mix is encoded to AC-3 and bitstreamed to HDMI. It has two parts:

- `driver/` — a PortCls WaveRT kernel driver (C++, KMDF 1.15, derived from Microsoft's SimpleAudioSample, MS-PL). It exposes one 6-channel render endpoint and moves no data itself; position and notifications are timer/QPC driven.
- `service/` — `win51svc.exe` (C++20, user mode). It runs this pipeline: WASAPI loopback of the Win51 endpoint → jitter buffer with drift correction → libavcodec AC-3 → IEC 61937 bursts → WASAPI exclusive, event-driven HDMI output. It runs as the Windows service `win51svc` and serves a control pipe.
- `tray/` — `win51tray.exe` (C++20, Win32). A notification area icon that shows the service state and sends commands through the control pipe.
- `installer/` and `tools/setup.ps1` — an Inno Setup installer that wraps `setup.ps1`, which does the actual install, update and uninstall.

## Invariants — keep these consistent across files

- **Channel masks.** Windows sees exactly one configuration, `KSAUDIO_SPEAKER_5POINT1` (0x3F, back surrounds). It is set in:
  - the driver formats (`speakerwavtable.h`) and the jack channel mapping (`speakertoptable.h`);
  - the INF (`PKEY_AudioEndpoint_PhysicalSpeakers` and the OEMFormat blob).

  A second mask makes the speaker setup list two "5.1 Surround" entries. `IsFormatSupported` matches the mask exactly, so the format table alone decides what Windows offers.
- **Encoder order.** Inside the service the order is FL FR FC LFE SL SR (`kMask51Side`, 0x60F). That is libavcodec's native order, so no reordering happens. `LoopbackSource::Open` maps back and side surrounds of any mix format onto SL/SR: AC-3 has one surround pair either way.
- **48 kHz only**, in the driver ranges and in the service checks.
- **IEC 61937 for AC-3:** a burst of 1536 frames × 4 bytes = 6144 bytes; `Pa=0xF872`, `Pb=0x4E1F`, `Pc = 1 | bsmod << 8`, `Pd` = payload length in bits; payload byte-swapped into 16-bit words.
- **The HDMI output never stops.** Silence is encoded too, so the receiver stays locked. Do not "optimise" this away.
- **No volume/mute nodes in the driver.** Windows then applies volume in software, and it reaches the loopback.
- **Version** lives only in `Directory.Build.props`. The projects pass it on as `WIN51_VERSION_DOTTED`/`WIN51_VERSION_NUM`: rc.exe cannot take a quoted string define. It also goes to stampinf `<TimeStamp>` (INF DriverVer) and to the installer. Without `<TimeStamp>`, stampinf stamps a time-based version, and such stale packages outrank real versions in the driver store. Windows does not replace a driver package with the same DriverVer, so bump the version to ship driver changes; `setup.ps1` skips the driver when the installed version is the same.
- **Control pipe protocol** (`shared/win51_control.h`): the service (`control_pipe.cpp`), the tray and the README describe it. Change all of them together; keep replies line-based `key=value`.
- **Log format.** The periodic stats line is documented in the README and read by people. Change both together.

## Building and verifying

Building works only on Windows, with the Enterprise WDK. There is no unit test suite. Verification means:

1. `tools\build.ps1` succeeds. All three projects build with `/W4 /WX`, so a warning is an error.
2. Offline encoder check, no hardware involved: `win51svc tone --out none --seconds 12 --dump t.spdif`, then `python3 tools/analyze_dump.py t.spdif`. Each channel should light up in turn: FL, FC, FR, SR, SL, LFE.
3. On the target, the service log (`C:\ProgramData\Win51\win51svc.log`) shows the expected stats. See *Diagnostics* in the README for normal values. `win51svc ctl status` shows the live state.
4. Control path: `win51svc ctl pause|resume|output <name>|output`, with the result checked in `ctl status` and in the log.

Dependencies go to `deps\` (gitignored): the EWDK ISO, an FFmpeg lgpl-shared win64 build (FFmpeg ≥ 5.1) and, for the installer, a portable Inno Setup in `deps\innosetup`. Output goes to `out\` (gitignored): the bundle `out\win51\`, `Win51-<version>-x64.zip` and `Win51-Setup-<version>.exe`.

## Working on a remote Windows PC

The maintainer develops on another machine and builds on the Windows PC over SSH (Win32-OpenSSH with PowerShell as the default shell):

- `tools/sync.sh` copies the tree. `WIN_HOST` and `WIN_DIR` override the SSH host and the target directory.
- Windows OpenSSH strips double quotes from the remote command line. For anything non-trivial, send a script as `powershell -NoProfile -EncodedCommand <base64 of UTF-16LE>`. Prefix it with `[Console]::OutputEncoding=[Text.Encoding]::UTF8`, since localized Windows prints non-ASCII text.
- Processes started over SSH die when the session ends. Long-running things belong in the service, not in an SSH session.
- Key-based SSH logons have no DPAPI access. That is why the signing certificate lives in `Cert:\LocalMachine\My`.
- Deploy: `out\Win51-Setup-<version>.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART`, or `setup.ps1` from the bundle. Either restarts the service (a few seconds of silence); a new driver version also restarts the device, and the service recovers by itself. The installer's own log goes where `/LOG=<file>` says; `setup.ps1` writes `C:\ProgramData\Win51\setup.log`.
- The tray icon must run in the user's desktop session, which SSH is not. Start it there with a one-off scheduled task (`New-ScheduledTaskPrincipal -LogonType Interactive`, run, then unregister).
- Release the output (`win51svc ctl pause`) before running `win51svc tone` or `run`: they need the HDMI output exclusively.

## Rules

- **Never change boot or security configuration on the user's machine.** That covers `bcdedit`, Secure Boot, BitLocker, certificate trust stores (Root, TrustedPublisher) and driver signature policy. `setup.ps1` and the installer make such changes when test mode is not on yet or the certificate is not trusted, and `setup.ps1 -Uninstall` reverts them. On a machine where test mode is on and the certificate is trusted, installing changes neither. Do not run them anywhere else; leave that to the owner.
- A driver bug crashes the machine (bugcheck). Keep driver changes minimal, reason about IRQL (most stream code runs at DISPATCH_LEVEL under a spin lock) and paged/non-paged code, and say so when a change has not been run on real hardware.
- Keep the Microsoft copyright headers in `driver/` files; they are MS-PL derivatives.
- Style:
  - match the surrounding code;
  - comments in English and short;
  - C++ sources are UTF-8 and compiled with `/utf-8`;
  - PowerShell scripts must run on Windows PowerShell 5.1 and stay ASCII-only, because 5.1 reads BOM-less files in the ANSI code page.
- Documentation changes go into both `README.md` and `README.ru.md`.
